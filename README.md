# Byte8 Horizon — Magento 2 Extension

Make your Magento catalog visible to AI. This is the companion extension for **[Byte8 Horizon](https://byte8.io/products/horizon)** — a hosted MCP (Model Context Protocol) gateway that lets AI agents like Claude, ChatGPT, and agent frameworks search your products, check stock, and quote real prices in real time. It also powers the **AI Shopping Assistant**, an on-site chat widget for your own storefront.

- 🛰 **Product**: [byte8.io/products/horizon](https://byte8.io/products/horizon)
- 📚 **Documentation**: [docs.byte8.io/horizon](https://docs.byte8.io/horizon/)
- 🖥 **Dashboard**: [horizon.byte8.io](https://horizon.byte8.io)

This module is **thin by design**: it publishes a read-only, AI-friendly API on your store and injects the assistant widget. The MCP protocol, agent auth, rate limiting, usage analytics, and the AI itself all live in the Byte8-hosted gateway — you don't run any long-lived service.

## Features

- **AI-friendly read API** — mounts `/horizon/api/v1/*`: product search, product detail, categories, MSI-aware inventory, orders, customers, **shipping estimates** (live carrier rates for a SKU to a country/postcode, computed on a throwaway quote — nothing is saved) and **store info** (contact details, ships-to countries, active carriers and payment methods, your policy pages as plain text) and **content search** (CMS pages and Magefan Blog posts, searchable by keyword and readable as plain text, for guides and how-tos), shaped for AI consumption (no EAV joins, no attribute-set sprawl).
- **Arrival dates, computed by the module** — order detail carries shipments, tracking numbers and a `delivery_estimate` (earliest/latest arrival in the store timezone) from your **Delivery Estimates** settings: handling time, business-days switch and a per-carrier Transit Times table, with a fallback to times written in method titles such as "Standard Delivery (3-5 days)". The AI only reads the dates; it never counts days itself.
- **Flat AI index** — a denormalised `byte8_horizon_product_index` table with fulltext search, registered as a native Magento indexer (`byte8_horizon_product`). It takes part in `bin/magento indexer:reindex`, shows up in `indexer:status` and the admin Index Management grid, and supports both *Update on Save* and *Update by Schedule* (recommended for large catalogs and bulk imports: `bin/magento indexer:set-mode schedule byte8_horizon_product`). `bin/magento horizon:reindex` remains as an alias for a full rebuild.
- **AI Shopping Assistant widget** — one admin toggle injects an on-site chat assistant (works on Luma, Hyvä, and custom themes). Widget configuration is fetched from the gateway automatically — no keys to copy into templates. The widget's own copy follows the store view locale (English, German, French, Spanish, Italian, Dutch; English otherwise), and replies follow the shopper's language.
- **AI readiness facts** — the health endpoint reports where `robots.txt` comes from (static file, SEO Suite rules or Magento core) and which related modules are installed, and `/horizon/api/v1/ai-visibility` returns AI crawler visits and AI-assistant referral sessions recorded by the free `byte8/module-ai-visibility` module (installed with this one). The Horizon dashboard's **AI readiness** page builds on both.
- **Agent writes, opt-in** — a second, write-only key unlocks `POST /horizon/api/v1/admin/*`: CMS pages (`cms-page`), products one at a time or in bulk (`product`, `products`), categories (`category`, incl. move), attribute options (`attribute-options`), new attributes (`attribute`), order actions (`order/invoice`, `order/shipment`, `order/fulfil`, `order/comment`, `order/hold`, `order/cancel` — never refunds) and customers (`customer`, `customer/address`, `customer/newsletter` — no passwords, no email changes, no deletion). Scopes are enforced in the module, every write accepts `dry_run` and returns the field-by-field change set, new products / pages / categories are created **disabled**, price moves above a configurable cap and attributes outside a per-store allowlist are refused, unpaid orders are not shipped and paid orders are not cancelled unless the merchant says otherwise. Nothing is deleted through the API.
- **Catalog invalidation webhooks** — fire-and-forget notifications to the gateway on product/category/stock changes (3s timeout, never blocks a save).
- **Security-first** — single per-store API key (generated by the Horizon dashboard, stored encrypted in Magento config, constant-time compared on every request), read-only endpoints unless a separate write key is configured, master kill switch.

## Requirements

- Magento **2.4.6+** (Open Source or Adobe Commerce)
- PHP **8.2 – 8.5**
- MSI enabled (default in 2.4+)
- Outbound HTTPS to `*.byte8.io`
- A [Horizon account](https://byte8.io/products/horizon) (14-day free trial)

## Installation

The package ships from the Byte8 Composer registry ([Cargoman](https://cargoman.io)):

```bash
composer config repositories.byte8 composer https://cargoman.io
composer require byte8/module-horizon
bin/magento setup:upgrade
bin/magento cache:flush
bin/magento indexer:reindex byte8_horizon_product
```

## Configuration

**Stores → Configuration → Byte8 → Horizon** in Magento admin:

| Field | What it does |
|---|---|
| **Enabled** | Master kill switch for the `/horizon/api/v1/*` API. |
| **API key** | Paste the key issued when you add the store at [horizon.byte8.io](https://horizon.byte8.io) (shown once — rotate from the dashboard if lost). Stored encrypted, displayed masked. |
| **Gateway URL** | Pre-filled with `https://horizon.byte8.io` — enables invalidation webhooks and the assistant bootstrap. Only change it for a self-hosted or local gateway. |
| **AI Shopping Assistant → Enabled** | Injects the storefront chat widget. Enable the assistant for the store in your Horizon dashboard first. |
| **Delivery Estimates → Handling Time (days)** | Days from order to dispatch (default 1). Used for orders not yet shipped and for quotes to new shoppers. |
| **Delivery Estimates → Count Business Days Only** | Skip weekends when adding handling and transit days (default yes). |
| **Delivery Estimates → Transit Times** | Min/max days in transit per carrier, optionally per method code. Carriers without a row fall back to a time in their method title, e.g. "(3-5 days)". |
| **General → Write Key** | Optional. Agent write key issued by the Horizon dashboard; the only key accepted by `/horizon/api/v1/admin/*` (`cms-page`, `product`, `products`, `category`, `attribute-options`, `attribute`, `order/*`, `customer*`). The API Key stays read-only. |
| **General → Write Scopes** | What the write key may change: `cms:write` (CMS pages), `catalog:write` (products, categories, attributes), `sales:write` (invoice / ship / fulfil / comment / hold / cancel unpaid; never refunds), `customers:write` (create accounts without a password, profile, addresses, newsletter with recorded consent). Enforced on every write; every write supports `dry_run`. |
| **Agent Writes → Writable Product Attributes** | Attribute codes an agent may set under `attributes` on a product write (e.g. `color, size, manufacturer`). Name, descriptions, price, special price and dates, weight, URL key, meta fields, status, visibility, websites, categories and stock are always writable. Empty = no extra attributes. |
| **Agent Writes → Max Price Change (%)** | Refuse a price or special-price change that moves the current value by more than this percentage in one write (default 50; 0 = no cap). |
| **Agent Writes → Max Products Per Bulk Write** | Most SKUs one `products` call may touch (default 50). |
| **Agent Writes → Allow Shipping Unpaid Orders** | `sales:write`: may a shipment be created while the order still has an amount due (default No — invoice first). |
| **Agent Writes → Allow Online Capture** | `sales:write`: may an agent-created invoice capture through the payment provider when the method supports it (default Yes; No = offline captures only). |
| **Agent Writes → Writable Customer Attributes** | `customers:write`: custom customer attribute codes an agent may set. Names, group, DOB, gender, tax id and addresses are always writable; email, password and deletion never. Empty = none. |
| **AI Shopping Assistant → Load After Cookie / Required Cookie Value / Gate Passed Event** | Hold the chat widget back until a cookie exists — for age-verification or consent gates. Set the cookie name (e.g. `age-confirmation`), optionally the exact value it must carry (`true`) and the `window` event your gate fires when the visitor passes, so the widget appears instantly rather than at the next 1.5-second check. Empty = the widget loads on every page. |
| **AI Shopping Assistant → Knowledge Pages** | CMS pages the assistant may quote for delivery times, returns, refunds, payment and contact questions. Leave empty to auto-detect pages whose title or URL key mentions shipping, delivery, returns, FAQ, customer service, contact, terms or payment, in English, German, French, Spanish, Italian or Dutch. A selected page may be disabled in Magento — it then serves as assistant-only knowledge (read, never linked, not visible on the storefront). Selecting pages replaces auto-detection, so pick every page the assistant should know — and only those: the budget is 12,000 characters per selected page (6,000 per auto-detected page) and 24,000 in total, spent on assistant-only pages first, then policy-looking pages, then the rest. Legal and marketing pages (terms, privacy, home) crowd out the FAQ. |
| **AI Shopping Assistant → Widget Position / Bottom Offset / Side Offset** | Which corner the chat button sits in (bottom right or bottom left) and its distance in px from the page edges (default 24, max 400). Raise the bottom offset when the button overlaps your theme's back-to-top or cookie button; the chat panel opens above the button. |

Then click **Test connection** in the Horizon dashboard — a green check means agents can reach your catalog. Full walkthrough: [docs.byte8.io/horizon/docs/getting-started/quick-start](https://docs.byte8.io/horizon/docs/getting-started/quick-start).

## How it fits together

```
┌──────────────┐   MCP (Bearer)   ┌─────────────────────┐   X-Horizon-Key   ┌─────────────────┐
│  AI agents   │ ───────────────► │  Horizon gateway    │ ────────────────► │  Magento 2      │
│ Claude, GPT, │                  │  horizon.byte8.io   │  /horizon/api/v1/*│  (this module)  │
│ frameworks   │ ◄─────────────── │  (Byte8-hosted)     │ ◄──────────────── │                 │
└──────────────┘                  └─────────▲───────────┘                   └─────────────────┘
                                            │ chat (SSE)
                                  ┌─────────┴───────────┐
                                  │ Shopping Assistant  │  ← widget injected on your
                                  │ widget on your site │    storefront by this module
                                  └─────────────────────┘
```

One API key secures both directions: agents present it to the gateway as a bearer token; the gateway presents it to your store as `X-Horizon-Key`. Keys are issued and rotated from the dashboard.

## The AI Shopping Assistant

With the assistant enabled, shoppers get an on-site chat that answers product, delivery ("do you ship to W1S and what does it cost?" — answered from your real carrier rates), policy (delivery times, returns, payment — answered from your own CMS pages) and order questions grounded in your live store — Byte8 hosts the AI, and the assistant is deliberately read-only (no cart or checkout actions). Order lookups require the shopper's order number *and* checkout email, verified server-side, and return a redacted summary only. Details: [docs.byte8.io/horizon/docs/assistant](https://docs.byte8.io/horizon/docs/assistant).
